## 📥 Original Request

> **Origin**: Systems Architect — supersedes earlier `DEV-20260521-ROUTING-AUTOMATION` draft.

Council outputs and analyst reports currently land in the wrong places. Recent observation: Boardroom outputs route to `AI-Help/cognitive-os/` instead of `dev/proposals/`. This proposal defines a **deterministic, regex/YAML-driven** routing layer that parses synthesis text, classifies it, and writes to the correct destination — with the new governance writers from Phase 1.

---

## 🎯 Goal

After this lands:
- Every council synthesis flows through `OutputRouter.route()` → typed `RoutingDecision` → deterministic destination.
- Analyst reports dropped into `dev/reports/` are auto-triaged by severity; HIGH escalates to Boardroom queue, MEDIUM/LOW land in backlog.
- **Single-writer rule**: `output_router` writes ONLY to backend (`dev/proposals/`, `dev/decisions/`); `proposal_sync` remains the sole vault writer. No race conditions, no double-writes.
- API response includes `routing_decision` so the dashboard knows where the artifact landed.

## ✅ v1.1 — Mandatory Hardening from Boardroom Review (2026-05-23)

The ORCHESTRATED_BOARD_CHAIRMAN council (task `task_20260523_120739_87ef198b`) returned **APPROVED WITH HARDENING** after all 11 roles completed cleanly. Eight concrete enhancements (E1-E8) must be baked in before Beta Testing; v1.0's 5 vetoes are reaffirmed as binding.

### E1-E8 Mandatory Hardening Enhancements

| # | Enhancement | Why |
|---|-------------|-----|
| **E1** | Add a **catch-all `decision_only` default route** in `routing_rules.yaml` for any synthesis that doesn't match the 7 specified rules | Prevents silent data loss for unmatched outputs (e.g., a council synthesis that lacks any known marker). Without it, the output_router would silently drop the content. |
| **E2** | **Permanent CI regression suite** using the 7 fixture council outputs + golden `RoutingDecision` JSON for each | Catches regressions when rules change. Tests must run in CI, not just locally. |
| **E3** | **Pydantic schema validation** for `config/routing_rules.yaml` at FastAPI startup | Fail-fast on malformed rules; don't wait for first synthesis to discover a typo. |
| **E4** | **Single-writer rule enforced via RUNTIME guard** (e.g., an import-time check that raises if a forbidden module imports the vault writer) OR a filesystem lock | Grep checks in CI are NOT enough — Logical role explicitly flagged this. A runtime guard catches violations the moment they happen, not at next CI run. |
| **E5** | **Structured error handling** in `output_router.apply()` with a `dev/failed_routings/` dead-letter directory for any write that throws | No silent drops on routing failures. Every failure is recoverable from the dead-letter dir. |
| **E6** | **Idempotency** in `workflow_router.py` polling loop: track processed files via SHA256 checksums or `.processed` flags | Prevents duplicate escalations on watcher restart — the watcher won't re-fire on files it has already routed. |
| **E7** | **Standardize regex boundaries** (`\b` word boundaries) for all markers | Prevents false positives like `#boardroom` matching inside `#boardrooming` or similar. |
| **E8** | Regex patterns + rules are **version-controlled as code**, with explicit testing required for any change | Every routing rule change is a reviewable commit. No hot-patching. |

### Affirmed Binding Vetoes (from v1.0; reaffirmed by chairman)

| # | Veto |
|---|------|
| **V1** | No LLM-based routing decisions — pure regex/YAML only |
| **V2** | No reintroduction of inline string-matching in `api.py` |
| **V3** | `output_router` must NEVER write directly to the vault |
| **V4** | Workflow router must run in a **background task via FastAPI lifespan**, NOT in the main event loop |
| **V5** | No "soft" routing rules — decisions must be deterministic and auditable |

### Concrete implementation order (recommended)

1. **`config/routing_rules.yaml`** with all 7 rules + E1 catch-all `decision_only`
2. **`src/routing_rules_schema.py`** (E3 Pydantic model) loaded at FastAPI startup
3. **`src/output_router.py`** with E5 dead-letter handling + E7 regex word boundaries
4. **`src/workflow_router.py`** with E6 checksum-based idempotency tracker
5. **CI regression suite** (E2) — 7 fixture inputs + golden outputs in `cognitive-os/tests/routing/`
6. **Runtime single-writer guard** (E4) — import-time check in `src/output_router.py.__init__` that scans the call stack or uses an importlib hook
7. Wire `api.py /process` to call `output_router.route(...)` — delete the inline string-matching

## ✅ v1.2 — Technical Board Refinements (2026-05-23)

The ORCHESTRATED_TECHNICAL_OVERSEER council (task `task_20260523_123308_27aec4f0`) confirmed v1.1's E1-E8 hardening and added two concrete architectural decisions. All three reviewer roles + their brand-guards approved.

The Creative role proposed "artistic signatures" in routing rules; Brand Guard correctly **rejected** this as out-of-scope and violating the deterministic-only mandate (V1+V5). Good signal that the brand-guards are doing their job rejecting scope creep.

### T1-T2 Architectural Refinements (binding)

| # | Refinement | Why |
|---|------------|-----|
| **T1** | **Interface Segregation for single-writer rule**: Define `BackendWriterProtocol` (output_router uses this) and `VaultWriterProtocol` (only `proposal_sync.py` implements). Runtime **import-time guard** raises immediately if OutputRouter imports or instantiates a `VaultWriterProtocol` class. | Concretizes E4 from "runtime guard" (vague) to a Python `typing.Protocol` + import-hook architecture. Cleaner than ad-hoc stack inspection. Catches violations the moment they happen. |
| **T2** | **Stateful markdown parser** for fence stripping: replace naive regex with a state machine that tracks whether we're inside a ` ``` `-fenced code block. Match markers ONLY outside fences. | E7's `\b` word boundaries aren't enough — a marker like `#boardroom` inside a code block must be ignored. Tiny state machine, not clever regex. |

### Affirmed Vetoes (from chairman)

| # | Veto |
|---|------|
| **T-V1** | No LLM-based routing decisions; pure regex/YAML only |
| **T-V2** | No direct vault writes by OutputRouter; **runtime guard enforced** (per T1) |
| **T-V3** | No blocking I/O on the main FastAPI event loop |
| **T-V4** | No fragile regex for markdown fence stripping; stateful parser required (per T2) |

### Implementation order (recommended; supersedes v1.1's order)

1. **`src/writer_protocols.py`** (T1): define `BackendWriterProtocol` and `VaultWriterProtocol` typing.Protocol classes.
2. **`src/markdown_fence_parser.py`** (T2): stateful preprocessor that strips fences before marker matching.
3. **`config/routing_rules.yaml`** with 7 rules + E1 catch-all.
4. **`src/routing_rules_schema.py`** (E3): Pydantic model loaded at FastAPI startup.
5. **`src/output_router.py`** with E5 dead-letter handling, E7 word boundaries, T1 protocol compliance.
6. **`src/workflow_router.py`** with E6 checksum idempotency, V4 lifespan-task wiring.
7. **Import-time guard** in `src/output_router.py.__init__` (T1): if VaultWriterProtocol class is imported, raise immediately.
8. **CI regression suite** (E2): 7 fixture inputs + golden RoutingDecision JSON.
9. Wire `api.py /process` to use `output_router.route(...)` — delete inline string-matching (V2).

### Module breakdown

| Module | Owns | Replaces |
|---|---|---|
| `src/output_router.py` | Marker parsing, routing rules, single-writer apply step | The inline string-matching in `api.py:/process` |
| `src/workflow_router.py` | Polling-based analyst report watcher + severity triage | Currently no equivalent; new capability |
| `config/routing_rules.yaml` (NEW) | 7 deterministic routing rules (table below) | Hardcoded `if "#boardroom" in text` strings |
| `dev/templates/report-template.md` | Created in Phase 1; referenced here |   |

### Routing rules (YAML-driven, no LLM)

| Rule name | Markers required | Severity | Action | Kanban column | Notes |
|---|---|---|---|---|---|
| `boardroom_proposal` | `#boardroom` + `definitive_blueprint:` | HIGH | `create_proposal` | `proposal` | Standard high-severity council approval |
| `technical_proposal` | `#technical` + `definitive_blueprint:` | MEDIUM | `create_proposal` | `backlog` | Tech board recommendation |
| `boardroom_synthesis` | `#boardroom` only | any | `write_decision` | (no change) | Log only, no artifact |
| `technical_synthesis` | `#technical` only | any | `write_decision` | (no change) | Log only, no artifact |
| `analyst_report_high` | `analyst_report:` marker | HIGH | `create_proposal` | `proposal` | Auto-escalate |
| `analyst_report_low` | `analyst_report:` marker | MEDIUM\|LOW | `enqueue_backlog` | `backlog` | Wait for human prioritisation |
| `decision_only` | `final_decision:` or `audit_report:` | any | `write_decision` | (no change) | Decision log entry only |

Regex set (case-insensitive, all compiled once at module load):
- `r'#severity:(high|medium|low)'`
- `r'#boardroom\b'`
- `r'#technical\b'`
- `r'definitive_blueprint:'`
- `r'final_decision:'`
- `r'analyst_report:'`
- `r'audit_report:'`

### Contracts at module boundaries

| From | To | Carrier |
|---|---|---|
| `output_router.parse_markers(text)` | router internal | `Markers` dataclass: `{severity, has_boardroom, has_technical, has_blueprint, has_decision, has_analyst, has_audit}` |
| `output_router.route(synthesis, context)` | caller | `RoutingDecision`: `{rule_name, action, target_column, target_path, reason}` |
| `output_router.apply(decision)` | caller | `ArtifactRefs`: `{proposal_id?, decision_log_path?, kanban_card_id?}` — fields populated by action type |
| `/process` response | dashboard | Existing response + `"routing_decision": RoutingDecision.dict()` |
| `workflow_router` | `output_router` | Submits an `AnalystReport` (validated by `schema_validator`) and gets a `RoutingDecision` back |

### Single-writer rule (the dual-writer fix flagged by analysis)

| Writer | Writes to | Forbidden to write |
|---|---|---|
| `output_router.apply()` | `dev/proposals/`, `dev/decisions/` only | `<vault>/...` (NEVER) |
| `proposal_sync` | `<vault>/...` only | `dev/proposals/` (NEVER — already true, made explicit) |
| `proposal_writer.create_proposal` (Phase 0) | Both, via current logic | After Phase 2 lands: backend only; `proposal_sync` mirrors to vault |

This eliminates the race where two writers touch the same file with no lock.

## ⚠️ Difficulties & Constraints

1. **Technical**: `/process` is async; `output_router.apply` does file I/O — wrap in `asyncio.to_thread`.
2. **Technical**: Polling watcher (5s default) instead of inotify because Windows is the dev OS. Configurable interval in `master_config.md`.
3. **Technical**: Marker regexes must NOT match markers inside fenced code blocks. Strip ` ```...``` ` blocks before parsing.
4. **Operational**: The existing 90 lines of inline routing in `api.py /process` are removed and replaced with `output_router.route(...)` call. Existing dashboard contract preserved.
5. **Aesthetic / Sovereign**: All routing decisions are auditable text. No model scoring, no "AI decided". Dark Maestro principle preserved.
