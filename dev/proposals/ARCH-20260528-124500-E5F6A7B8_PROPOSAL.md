## Original Request

Architecture Extension: Alpha & Final Audit Pattern Modules, plus Strict Gate Controls (Depends on ARCH-7C4E2B91)

As we decompose the orchestrator (`ARCH-20260526-093000-7C4E2B91`), the Kanban transition workflow for the later stages of the development lifecycle still lacks proper specialization and validation:
1. **Weak Beta → Alpha Gate:** Moving a card from Beta Testing to Alpha Polish currently relies on a naive file-system check (does `BETA_HANDOFF.md` exist?). It does not validate if the actual implementation tasks are marked as complete or if the test suite is passing.
2. **Alpha Polish Overkill:** Moving a card to `alpha polish` triggers the entire 5-seat Sequential Boardroom. This is misaligned with the goals of the Alpha phase, which should focus purely on UI/UX refinement, performance optimization, and hardening.
3. **Missing Finalized Quality Gate:** The transition from Alpha Polish to Finalized similarly relies only on checking if `ALPHA_HANDOFF.md` exists. 
4. **Dormant Roles:** A `dev_final_audit` role exists in `master_config.md` but is entirely disconnected from the transition flow.

---

## LLM Technical Assessment

**Proposed Solution:**
Build upon the new `src/patterns/` architecture from ARCH-7C4E2B91. Introduce two new dedicated pattern modules that enforce strict quality gates for the Alpha and Finalized phases, and tighten the Beta exit gate.

**1. Strengthen the Beta → Alpha Gate**
Update the transition logic in `src/api.py` so that entering Alpha Polish requires more than just the existence of the handoff file. It must parse the `BETA_HANDOFF.md` to ensure all tasks are checked off, and hook into the test runner to ensure tests are passing before allowing the transition.

**2. Create `src/patterns/alpha_council.py`**
Replace the Sequential Boardroom trigger in the Alpha phase with a dedicated pattern module. This council uses `council_runner.run_council` with the following specialized sequence:
*   `alpha_ux_specialist`: Focuses strictly on UI/UX friction, accessibility, and visual feedback.
*   `alpha_perf_specialist`: Focuses on algorithmic bottlenecks, latency, database queries, and memory leaks.
*   `alpha_critic`: Hunts for edge cases, race conditions, and security vulnerabilities.
*   `dev_alpha_polish` (Synthesis Role): Reconciles the inputs into a definitive JSON blueprint, which is then passed to the `handoff_writer` to generate `ALPHA_HANDOFF.md`.

**3. Create `src/patterns/final_audit.py`**
Triggered when moving a card to `finalized`. This pattern acts as a strict quality gate:
*   `final_scribe`: Ingests the original proposal, Beta/Alpha handoff documents, and implementation details to write comprehensive, user-facing release notes and documentation.
*   `dev_final_audit` (Synthesis Role): Acts as the ultimate release gate. Evaluates the documentation and code state against project requirements and outputs a strict `{"final_verdict": "APPROVED" | "REJECTED"}` JSON response.

**4. API & Transition Updates**
*   Update `src/api.py` (`_run_alpha_council_and_handoff` and `_finalize_proposal` hooks) to call the new pattern modules instead of the old orchestrator methods.
*   Modify the Kanban transition logic to physically block transitions to `alpha polish` and `deployed` if the validation checks or the `dev_final_audit` returns a `REJECTED` verdict.

**Files to Modify:**
*   `dev/master_config.md` (Add the 4 new role definitions, wire them up)
*   `src/patterns/alpha_council.py` (New file)
*   `src/patterns/final_audit.py` (New file)
*   `src/api.py` (Update transition triggers and hard gates)
*   `dashboard/script.js` (Optional: update UI logic to surface the "REJECTED" state if the audit fails)
