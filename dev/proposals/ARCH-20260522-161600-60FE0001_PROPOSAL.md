## 📥 Original Request

> **Origin**: Systems Architect agent — supersedes the earlier `DEV-20260521-GOVERNANCE-FOUNDATION` draft (preserved as a Boardroom council task in `council_memory/archived/`).

Define the **data foundation** for the governance framework: Pydantic models that describe the proposal lifecycle, a schema validator that enforces required YAML fields at every entry point, an immutable content-addressable handoff vault, and an append-only approval log. This is the layer everything else (routing, workflow engine) sits on.

---

## 🎯 Goal

After this proposal lands:
- Every proposal carries a typed shape (`ValidatedProposal`) with `severity`, `origin`, `workflow_version`, `phase`, `status` enforced at the schema boundary.
- Every state-change writes an immutable snapshot to `dev/.archives/` with a SHA256 hash of the content.
- Every approval/rejection appends to a per-proposal decision log + indexed in SQLite for fast queries.
- A killed process mid-write recovers from the vault on next boot. **Zero data loss.**

## ✅ v1.1 — Mandatory Refinements from Boardroom Review (2026-05-23)

The ORCHESTRATED_BOARD_CHAIRMAN council (task `task_20260523_110721_b67eaae6`) returned **APPROVED with Mandatory Technical Refinements** after identifying 4 critical I/O vulnerabilities. Card stays in `Proposal` column until v1.1 implementation refinements are confirmed; only then does it move to Beta Testing.

### Binding Vetoes (must be addressed before any implementation)

| # | Veto | Fix |
|---|------|-----|
| **V1** | `ArtifactVersion` containing full proposal `body` field → storage bloat as proposals/snapshots grow | Refactor `ArtifactVersion` to store **only `path + sha256_hash`** (content-addressable pointer). The body lives on disk in the snapshot file; metadata in `dev/.archives/index.sqlite` stores only path + hash + phase + timestamp + prior_hash. |
| **V2** | Line-count-based integrity for decision logs → trivially spoofed (an attacker can rewrite any line as long as count matches) | Replace line-count checks with **full-file SHA256 verification**. SQLite index stores the last-known SHA256 of each decision log. `verify_chain` recomputes and compares. |
| **V3** | Standard SQLite configuration inside async event loop → event-loop contention, blocked writes | Configure SQLite with **WAL mode** (`PRAGMA journal_mode=WAL`) AND **`PRAGMA synchronous=NORMAL`**. All writes via `asyncio.to_thread`. Single async-safe connection pool (matches DA5B0A2D H1-refined). |
| **V4** | Atomic rename without explicit `fsync` → data loss on crash mid-write (file exists but content not flushed to disk) | Implement atomic writes with **explicit `os.fsync(fd)` BEFORE `os.replace(tmp, final)`** for both proposal files AND vault snapshots. Test with SIGKILL crash recovery. |

### Implementation Refinements (mandatory but not blocking)

| # | Refinement |
|---|-----------|
| **R5** | Phased validation: start in **WARN mode**, monitor dashboard warnings, require **explicit Boardroom approval** before flipping to REJECT mode. (Already in v1.0; explicitly affirmed as binding.) |
| **R6** | All governance operations use **structured JSON logging**. Route to `stderr` only in non-containerized / dev mode. In production (TBD container detection), route to a proper logger sink (file or remote). |

### Effect on existing v1.0 design

- `workflow_models.ArtifactVersion` schema changes: drop `body: str`, keep `proposal_id, phase, timestamp, sha256, prior_hash, snapshot_path`.
- `handoff_vault.snapshot()` writes the full markdown body to a file at `snapshot_path`, then writes ONLY the metadata record to SQLite.
- `handoff_vault.restore(hash)` reads the file at `snapshot_path` after verifying its content hash matches.
- `approval_logger.verify_chain(proposal_id)` now recomputes file hashes instead of comparing line counts.
- All `open(...)` calls for snapshot/log writes use the pattern: `write to tmp → fsync → atomic rename`.

## ✅ v1.2 — Chairman's Blueprint Refinements from Technical Board (2026-05-23)

The ORCHESTRATED_TECHNICAL_OVERSEER council (task `task_20260523_114356_62f650b5`) confirmed v1.1 vetoes V1-V4 were correctly integrated and added concrete architectural refinements + 6 new binding vetoes.

### B1-B7 Blueprint Refinements (binding architectural decisions)

| # | Refinement | Rationale |
|---|-----------|-----------|
| **B1** | **"Dual-Truth" architecture**: Markdown = human source of truth; SQLite = high-performance index | Cleaner mental model than v1.1's "vault + index". Documents the layering explicitly. |
| **B2** | `aiosqlite` is an acceptable alternative to `asyncio.to_thread` for SQLite I/O | Implementation choice deferred to coder; either is V3-compliant. Use whichever fits the surrounding API code style. |
| **B3** | **`GovernanceUnitOfWork` wrapper**: Markdown append + SQLite update treated as ONE logical transaction. Failure in either triggers rollback of `.tmp` files AND a critical-level stderr log | The missing piece v1.1 didn't spec. Without it, partial failures leave markdown and SQLite disagreeing — exactly the silent-drop pattern this proposal exists to eliminate. |
| **B4** | **Stronger chain-of-custody on decision logs**: each entry contains `nonce + timestamp + sha256_of_preceding_record` | v1.1's V2 only required full-file SHA256. B4 makes each line independently verifiable — tamper detection is per-entry, not per-file. |
| **B5** | **Boot-time manifest generator**: at API startup, hash every proposal + decision log + archive snapshot; compare against SQLite index. Any mismatch logged as a tampering event | Optional but elegant. Can land in Alpha Polish phase. |
| **B6** | Use **`ruamel.yaml`** (NOT PyYAML) for the legacy migration utility | ruamel preserves comments + key ordering. PyYAML rewrites the file destructively. Critical for the 59 existing proposals' YAML frontmatter. |
| **B7** | **Network-FS caveat**: V4 (fsync before rename) is MANDATORY, not optional — atomic-rename semantics differ on NFS/SMB and only explicit `os.fsync(fd)` covers those cases | Identified by Technical Critic. Test must include a network-mounted scratch dir if available. |

### V5-V10 Binding Vetoes (added by overseer; join V1-V4 from v1.1)

| # | Veto |
|---|------|
| **V5** | No business logic or I/O in `workflow_models.py` — pure Pydantic only |
| **V6** | No blocking SQLite/File calls in the main async event loop |
| **V7** | (Restates V1) No storage of full proposal bodies in `ArtifactVersion` |
| **V8** | No flipping to REJECT mode until dashboard warnings are zeroed (was R5 in v1.1; promoted to veto) |
| **V9** | No silent exception swallowing — generic `except: pass` is strictly forbidden |
| **V10** | No direct writes to `dev/.archives/` outside of `handoff_vault.py` |

### Implementation order (recommended)

1. **`src/workflow_models.py`** (pure types; no I/O) — V5-compliant Pydantic models including pointer-shaped `ArtifactVersion`.
2. **`src/schema_validator.py`** — phased WARN/REJECT mode; uses `ruamel.yaml` (B6) for the migration utility.
3. **`src/handoff_vault.py`** — sole writer to `dev/.archives/` (V10); content-addressable storage; write-tmp + fsync + atomic-rename (V4 + B7).
4. **`src/approval_logger.py`** — markdown source of truth (B1); SQLite index with WAL + sync=NORMAL (V3); per-entry chain-of-custody (B4).
5. **`src/governance_unit_of_work.py`** (B3) — the transactional wrapper. Implementations of (3) and (4) wrap their writes through this.
6. API endpoints — strictly typed Pydantic shapes.
7. **(Alpha Polish)** Boot-time manifest generator (B5).

## ⚠️ Difficulties & Constraints

1. **Technical**: The legacy migration MUST be idempotent — running it twice produces zero diff. Acceptance criterion below covers this.
2. **Technical**: SQLite write contention with FastAPI's async event loop — every write goes through `asyncio.to_thread`.
3. **Operational**: WARN → REJECT flip is a config flag (`schema_validation_mode: warn | reject` in `master_config.md`). Flip is a manual Boardroom decision, not automatic.
4. **Aesthetic / Sovereign**: Decision logs are user-readable markdown. SQLite is invisible — index only. The vault remains the source of truth so the user can always read the system's mind without opening a DB.

## 🚫 Veto Points

- ❌ Putting business logic in `workflow_models.py` — it MUST be pure type definitions, no I/O.
- ❌ Editing the SQLite index without also appending to the markdown log — markdown is source of truth.
- ❌ Flipping schema_validation_mode to `reject` before warn-mode has zero outstanding violations on the dashboard.
- ❌ Catching `Exception` in any new module without re-raising or explicitly logging to stderr (see Data Flow Tracer bug catalog — this exact pattern caused the silent-drop incidents).
- ❌ Writing to `dev/.archives/` from any module other than `handoff_vault.py`.
- ❌ Allowing the migration to delete or rename existing proposals.
