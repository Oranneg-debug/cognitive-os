## 📥 Original Request

> **Origin**: Systems Architect — captured from observed production behavior on 2026-05-23.

The 5-phase governance stack (Phase 0 refactor through Phase 3+4 workflow execution) is on disk, tested in isolation, all 35 gates green, 155 tests passing. **But it does not run in production.** No FastAPI endpoint, no Telegram handler, no kanban watcher, no orchestrator path actually imports the new modules.

**Evidence (2026-05-23 23:40):** A boardroom council fired on ARCH-78D36EDB and produced a clean `APPROVED WITH CONDITIONS` verdict. The verdict was synthesised correctly, but **landed in `AI-Help/cognitive-os/OLMRboardroomARCHPROPOSALProposalID.md`** — the legacy fallback path — instead of `dev/decisions/ARCH-78D36EDB_boardroom_decision.md`. The OutputRouter that exists to prevent this exact misrouting was never called.

This proposal wires the new architecture into the four production services so it actually does its job.

- **No new architecture is built** — only wiring of what's already tested

## ✅ Deliverables

### Section A — Service wiring (the core integration)

1. **`api.py /process` → OutputRouter**
   - Remove the inline string-matching that decides where to write council synthesis
   - Instantiate `OutputRouter(rules_path=PATHS_TO.routing_rules, backend_writer=<inject>, dead_letter_dir=PATHS_TO.failed_routings)` at app startup
   - `/process` endpoint calls `router.route(synthesis)` → `router.apply(synthesis, decision)`
   - Include the returned `RoutingDecision` in the API response (the dashboard already expects this field per the proposal)

2. **`orchestrator.py` → OutputRouter**
   - Same pattern: orchestrator stops writing council output directly; it returns the synthesis to `api.py` which routes it
   - OR orchestrator gets its own injected `OutputRouter` instance — pick whichever needs less plumbing

3. **`kanban_processor.py` → workflow_engine**
   - All kanban-triggered phase transitions go through `workflow_engine.transition(TransitionRequest(...))`
   - The existing `transition_rules` dict becomes the *fallback* (used when workflow_engine raises a hard veto, the transition is logged but not blocked, with a `# TODO: remove after migration` annotation)
   - After 30 days of clean operation in production, the fallback is deleted in a follow-up proposal

4. **`proposal_writer.py` + `handoff_writer.py` → GovernanceUnitOfWork**
   - Multi-file writes (proposal + handoff + sync trigger) wrap in `with GovernanceUnitOfWork() as uow:`
   - On failure, the UoW rolls back. No more partial-write states.

### Section B — Boot-time validation

5. **`api.py` startup** validates:
   - `config/routing_rules.yaml` loads cleanly via `load_routing_rules()` (E3 from Phase 2)
   - `config/state_machine.yaml` loads cleanly
   - `dev/failed_routings/` exists (create on boot if missing)
   - Composite index on `approval_log` exists in SQLite (Phase 1 should already do this in `ApprovalLogger.__init__`, verify it does)
   - If any of these fails, FastAPI refuses to start with a clear error

### Section C — Migration safety

6. **Feature flag** in `master_config.md`:
   ```yaml
   integration:
     output_router_enabled: true
     workflow_engine_enabled: true
     governance_uow_enabled: true
   ```
   Each defaults to `true`; setting to `false` reverts that subsystem to legacy behavior. Lets us flip individual integrations off if production reveals a bug, without reverting a commit.

7. **Migrate the legacy `AI-Help/cognitive-os/` dump** in a one-shot script:
   - `scripts/migrate_ai_help_legacy.py` reads each `OLMR*` file
   - Parses the embedded `Proposal ID` if present
   - Routes via `OutputRouter` to the correct destination
   - Moves the original to `AI-Help/cognitive-os/_migrated/`
   - Reports what couldn't be classified

### Section D — Tests

8. **Integration tests** in `tests/integration/`:
   - `test_api_process_uses_output_router.py` — boardroom synthesis from `/process` lands in correct dir
   - `test_kanban_transition_uses_workflow_engine.py` — phase changes go through workflow_engine
   - `test_orchestrator_no_legacy_fallback.py` — assert `AI-Help/cognitive-os/` does not receive new writes
   - `test_proposal_writer_uses_uow.py` — partial failure rolls back
   - Target: ≥10 integration test cases (the existing 155 unit tests stay)

9. **Smoke test fixture** in `scripts/smoke_phase5.py`:
   - Fires a fake boardroom via the API
   - Asserts the synthesis landed in `dev/decisions/`
   - Asserts the kanban card moved
   - Asserts the approval log gained an entry
   - Returns 0 if green, 1 + diagnostic dump if not
   - Run after every deploy
