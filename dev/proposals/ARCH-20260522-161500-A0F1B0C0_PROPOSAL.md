## 📥 Original Request

> **Origin**: Systems Architect agent — surfaced while reviewing the Complete Governance & Workflow Integration Plan v1.0.

Before any governance/workflow modules land, fix three structural defects in the current code that will multiply if ignored:

1. `_trigger_sync_check` is byte-duplicated across `dev_route.py` and `kanban_processor.py`. Phase 1-3 add two more callers (`workflow_engine`, `output_router`) → the 3-callers rule fires.
2. Vault root literal `"E:\\Oranneg\\…\\Grand Nexus"` is hardcoded in three modules. Phase 1-3 introduce four more modules that all need the same path.
3. `dev_route.py` is 1031 lines and owns proposal CRUD + Kanban writes + handoff generation + status updates + finalize. The Phase 3 proposal says "refactor dev_route.py" as a side-effect of workflow_engine — that order is backwards and inherits the coupling.

---

## 🎯 Goal

A clean substrate for governance work: one helper module for sync, one constants module for vault paths, and a `dev_route.py` split into three single-responsibility modules. **Pure refactor — no behaviour change.** All current API endpoints and Kanban automation continue working exactly as before.

### Modularity hotspots

1. **`_trigger_sync_check` duplication** — `dev_route.py:203` ≡ `kanban_processor.py:219`. Both have the same dead-code bug: `str(e) if 'e' in locals() else ...` — `e` is bound to the outer except clause if assignment never happens, so the fallback string is unreachable.
2. **`dev_route.py` god-class** — `create_proposal` (proposal lifecycle), `generate_beta_handoff` / `generate_alpha_handoff` (artifact synthesis), `_add_card_to_kanban` (board mutation), `finalize_release` (release lifecycle) all share `self.proposals_dir` but otherwise have no overlap.
3. **Vault path triplication** — same literal in `dev_route.py:62`, `proposal_sync.py:36`, `kanban_processor.py:100`.
4. **`transition_rules` defined twice** in `kanban_processor.py` — `__init__` reads from `_load_transition_rules` and also from `_STATUS_CONFIG.get("transition_rules", {})`. Pick one source.

## ⚠️ Difficulties & Constraints

1. **Technical**: `api.py`'s `from src.dev_route import DevRouteManager` must keep working. Solution: `dev_route.py` keeps the class and delegates internally — no caller change required.
2. **Technical (v1.1 — C5)**: The regex-based YAML status updaters in `dev_route.py` (e.g. `re.sub(r'\|\s*Lifecycle Phase\s*\|\s*…')`) are fragile but out of scope for this refactor. **Tracked as `ARCH-…-F10FE0E1-DEBT-01` in the tech-debt register**; Phase 3+4 (`workflow_engine`) must eliminate them.
3. **Operational (v1.1 — C1)**: Refactor lands as **an atomic feature branch, squashed on merge**, not a single live commit. This preserves clean revertability (one merge commit on `main`) without forcing one monolithic working commit during development.
4. **Technical (v1.1 — C3)**: Post-split, the import graph between `paths.py` → `sync_check.py` → `proposal_writer.py` / `handoff_writer.py` → `dev_route.py` (façade) must remain a DAG. Static analysis enforces this in CI.
5. **Technical (v1.1 — C4)**: `paths.py` MUST fail-fast at import time if vault path is unresolvable. Silent fallback to a non-existent directory is the exact silent-drop pattern Phase 1 is being built to fix; we will not introduce a new instance here.
6. **Aesthetic / Sovereign**: None — pure internal hygiene, no user-facing surface touched.

## 📋 Implementation Tasks (Beta Council will refine)

1. Create `src/paths.py` with all constants (Path objects). **(v1.1 — C4 + v1.2 — C4-refined)** Resolve `OBSIDIAN_VAULT_PATH` at import time; raise `RuntimeError` if env var is unset AND the explicit fallback directory does not exist on disk. No silent fallback. Use `pathlib.Path(p).is_dir()` (Path API handles Windows/POSIX/UNC + surfaces `PermissionError` distinctly from "not found") — do NOT use `os.path.exists()` alone (it returns False on permission errors, masking the real failure as "missing").
2. Create `src/sync_check.py` with `trigger_sync_check()` — single impl, fixes `'e' in locals()` dead code.
3. Replace `_trigger_sync_check` body in `dev_route.py` and `kanban_processor.py` with `return trigger_sync_check()`.
4. Create `src/proposal_writer.py`; move `create_proposal`, `_extract_card_title`, `_add_card_to_kanban`, `_get_kanban_template`, `sync_proposals` from `dev_route.py`.
5. Create `src/handoff_writer.py`; move `generate_beta_handoff`, `generate_alpha_handoff`, their `_extract_section` closures.
6. Slim `dev_route.py`: `DevRouteManager` becomes a façade; its methods call into the new modules.
7. Replace all hardcoded vault path literals with imports from `paths.py`.
8. Run existing `cognitive-os/tests/` and `cognitive-os/test_api_endpoints.py` — every assertion must still pass.
9. Re-run `test_sync.py` and `test_sync_simple.py` — both must pass without modification.
10. **(v1.1 — C1)** Develop on a feature branch (`feat/arch-A0F1B0C0-phase0-refactor`); merge with `--squash` so the merge commit on `main` is atomic and revertable as one unit.
11. **(v1.1 — C2)** Resolve `transition_rules` duplication in `kanban_processor.py`: unify to a single source. Pick `_STATUS_CONFIG.get("transition_rules", {})` (drives from JSON, easier to override) OR `_load_transition_rules()` (Python, clearer defaults) — not both. Remove the loser entirely.
12. **(v1.1 — C3)** Add a CI / pre-merge static-analysis check that the post-split import graph has no cycles. Tool: `pylint --disable=all --enable=cyclic-import cognitive-os/src/` OR `import-linter` configured in `pyproject.toml` (Beta Council picks the tool). Document the command in `cognitive-os/README.md` so future contributors can run it locally.
13. **(v1.1 — C5)** Append a row to `dev/decisions/_tech_debt_register.md` (create the file if absent) with tracking ID `ARCH-…-F10FE0E1-DEBT-01`, description "regex-based YAML status updaters in dev_route.py", target proposal `ARCH-20260522-161800-F10FE0E1`.
