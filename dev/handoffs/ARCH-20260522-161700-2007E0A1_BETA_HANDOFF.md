### **📋 Summary**
This proposal introduces a **deterministic, regex/YAML-driven routing layer** to replace ad-hoc string-matching in the current system. The system consists of two core components:

**Key Features:**
- **Deterministic Routing**: Pure regex/YAML rules with no LLM involvement.
- **Auditability**: All routing decisions are logged as structured JSON in `dev/routing_audit/`.
- **Idempotency**: WorkflowRouter uses SHA256 checksums + `.processed` flags to prevent duplicate triage.
- **Error Handling**: Failed writes are stored in `dev/failed_routings/` for recovery.

**Purpose:**
To eliminate manual routing errors (e.g., Boardroom outputs landing in `AI-Help/cognitive-os/` instead of `dev/proposals/`), enforce governance rules, and provide a scalable foundation for future extensions like artistic watermarking or semantic analysis.

---

### **🚨 Difficulties & Constraints**

#### **Technical Challenges**
1. **Async I/O Blocking**:
   - `OutputRouter.apply()` performs blocking filesystem operations (e.g., writing to directories). Without proper offloading, it risks event loop starvation.
   - *Mitigation*: Wrap all file I/O in `asyncio.to_thread` or use a ThreadPoolExecutor.

2. **Markdown Fence Stripping**:
   - Naive regex for removing code blocks (e.g., ````\s*([^`]+)\s*````) can fail on nested/unclosed fences, corrupting synthesis text.
   - *Mitigation*: Implement a stateful preprocessor or use a dedicated markdown parser library like `markdown-it`.

3. **Single-Writer Enforcement**:
   - Current enforcement relies solely on CI grep checks, which are insufficient for runtime safety.
   - *Mitigation*: Architectural boundary via abstract writer protocols (`BackendWriterProtocol`, `VaultWriterProtocol`). Only `proposal_sync.py` implements the vault protocol; all other writers must type-hint `BackendWriterProtocol`.

4. **Polling Watcher Latency**:
   - A 5-second polling interval introduces latency for real-time triage. Graceful shutdown must avoid task leaks.
   - *Mitigation*: Use a dedicated asyncio.Task with explicit cancellation handling and flush logic.

5. **Idempotency Overhead**:
   - SHA256 checksums on large reports add CPU cost, while `.processed` flags require cleanup to avoid stale markers.
   - *Mitigation*: Hybrid approach (SHA256 for critical files, `.processed` flags for smaller artifacts) with periodic cleanup.

   - *Impact*: Race conditions, data loss.
   - *Solution*: Architectural boundary via protocols + runtime guards.
